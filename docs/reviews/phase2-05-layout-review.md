## 3. 推荐方案 A：外置地图工具条 + 右侧短解释 + 底部紧凑时间轴

桌面继续采用两列主工作区，但缩窄详情列、压缩页头，并把时间轴改为跨两列的底部控制。地图内部只保留 MapLibre 导航、比例尺、署名和地图本身必须直接承载的交互。

### 3.2 紧凑底部时间轴

- 保留“上一事件”“下一事件”、当前事件标题/相对时间和“第 N / 6 个事件”。
- 六个事件改为单行位置按钮，只显示序号或短标签；每个按钮保留完整可访问名称，当前项使用 `aria-current="step"`。
- 保留现有左右方向键、带修饰键时不抢占、首尾禁用和点击任一事件位置的语义；焦点顺序为上一事件、事件位置、下一事件。
- 不在首屏铺开六张事件卡；完整标题和相对时间只在当前项摘要或按钮可访问名称中出现。

### 3.3 当前对象短解释与按需详情

- 事件：首屏保留 2 条核心结论，即“发生了什么”和“为什么重要”；时间精度、参与者与相关地点以紧凑元信息或入口保留。
- 地点：首屏保留 2—4 条已批准短结论，覆盖地点作用、受控方向和代表点/范围不确定性。
- 路线：保留 PHASE2-04 已批准的 4 条短说明，以及 `120/80/55 km` 和方向语义；不得改写成历史道路或行军里程。
- 每种对象都持续显示“完整引用与不确定性（N）”入口；完整 Citation、来源定位、项目归纳、方法边界和重复的不确定性说明放入原生可键盘操作的按需展开区。
- 折叠只改变呈现层级，不删除、不合并、不改写正式内容或来源关系。

### 3.4 地图控件与避让规则

- “定位当前事件”“地形已加载 · 俯视”“图层”“图例与不确定性”进入地图画布上方的紧凑工具条，不再覆盖潼关或路线；图层和图例同一时刻最多展开一个面板。
- MapLibre 导航保留左上；比例尺进入地图底部保留带的左侧；署名入口位于右侧。展开署名时使用有界、可滚动的许可面板，并通过同一底部布局带与比例尺避让，禁止绝对定位相互覆盖。
- 署名、Copernicus、Natural Earth、geoBoundaries 及二期来源文字保持持续可达；不得为了缩短首屏而隐藏许可入口。
- 潼关/路线的解释移至右侧短解释列；地图上的标签、路线箭头和点击命中仍由同一 Map/Canvas 承载。
- 任何弹出面板都不得盖住当前潼关、当前路线标签、比例尺或署名入口；1024 与 1440 分别用 overlay 矩形测量证明零重叠。

### 3.5 双 base 与迁移边界

- 根路径和 `/history-map/` 使用相同 Vue 组件、CSS 断点与布局目标；不得为子路径复制模板或维护另一套页面。
- 所有 worker、数据、地图样式和地形资产 URL 继续经现有 base 感知路径生成，不新增运行时外网或硬编码根路径。
- 只重排 `AnshiMvpView`、时间轴、详情呈现和地图控制的 DOM/CSS；Pinia 中事件、地点、路线选择和四组图层开关的状态语义不变。
- 保留地图拖动/缩放、事件逐段路线显隐、事件回退、地点/路线选择、四组图层开关、单 Map/Canvas，以及 `style.load` 幂等恢复和状态恢复。
- 布局重排不得触碰正式 JSON、RouteSegment 节点、方向/距离计算、审核状态或批准文案。

## 4. 替代方案

### 方案 B：全宽地图 + 可收起浮动解释抽屉

地图面积最大，1024 下也可获得接近全宽的地形视野；短解释从右侧浮层展开。

风险是解释抽屉、图层、图例和署名同时出现时容易遮挡路线与潼关，焦点管理和 1024 下的矩形避让更复杂，也更难保证“不操作即可同时看到地图和短解释”。不推荐作为 P-007 默认方案。

### 方案 C：全宽地图 + 地图下方解释条 + 最底部时间轴

没有右侧浮层，许可与地图控件避让最简单；但在 768 px 高度下，解释条和时间轴会共同压缩地图，或者再次落到首屏下方。适合作为窄屏降级，不推荐作为桌面主方案。
