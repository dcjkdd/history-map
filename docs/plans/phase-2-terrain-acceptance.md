# 安史之乱地形优先地图：二期验收

- 状态：当前发布门禁
- 范围：`docs/plans/phase-2-terrain-scope.md`
- 任务：`docs/plans/phase-2-terrain-tasks.md`
- 决策：`docs/decisions/0002-地形优先二期产品纠偏.md`

## 1. 验收原则

二期按以下顺序验收：

1. **产品价值**：地图本身能否解释地形、关隘和路线原因。
2. **空间表达**：地形、水系、地貌、通道、距离、关隘和路线是否形成一致空间叙事。
3. **内容可信度**：现代地理、历史资料、项目推断和争议是否明确区分并可追溯。
4. **工程质量**：交互、构建、静态部署、性能、worker、秘密和降级是否可靠。

自动测试通过不能代替产品价值；引用完整不能代替空间可读；三维效果存在不能代替军事地理解释。

## 2. P0 发布阻断条件

出现任一情况，二期不得称为第一可用产品：

- 默认首屏看不出明显地形起伏、平原/山地和河谷关系。
- 用户不知道当前区域位于河南、陕西及其相邻位置。
- 潼关仍只是普通点，无法从地图看出它控制的通道和周边约束。
- 路线仍主要表现为城市代表点之间的直尺线，且没有方向、距离或地形原因。
- 必须阅读长篇详情或引用后才知道军队为什么这样走。
- 黄河、渭河、秦岭或主要地貌标签不可辨认。
- 约略距离、现代代表点和解释性通道被表现成精确历史里程或道路。
- 新地形/边界/通道数据缺来源、版本、许可、署名或处理记录。
- 正常产品模式只能依赖个人 Token、未记录配额或不可公开再分发的数据。
- 根路径或 `/history-map/` 构建失败、地形资源缺失、worker 闭包失败、出现未处理异常或多个 MapLibre/Canvas。

中性空白降级只证明页面不会白屏，不能作为地形优先产品验收通过的证据。

## 3. 产品验收场景

### P-001：五秒空间判断

打开默认页面，不操作侧栏。

预期：

- 能指出长安、洛阳和潼关的大致相对方向。
- 能分辨主要山地、平原/低地和河流。
- 能看出潼关位于东西通道的关键位置，而不是散点之一。

### P-002：基本区域定位

预期：

- 页面提供省级边界或同等清晰的区域定位。
- 用户能判断主要故事跨越河南和陕西，不需要另开地图查询。
- 比例尺和方向控制可见、可用、不遮挡署名。

### P-003：为什么经过这里

选择燕军西进路线。

预期：

- 路线有明确方向。
- 地图和短解释同时指出北侧河流、南侧山地及东西通道关系。
- 页面明确路线为解释性示意，不是唐代道路复原。

### P-004：为什么潼关关键

选择潼关。

预期：

- 关隘符号与城市明显不同。
- 地图视野同时保留河流、山地、通道和东西两侧节点。
- 2—4 条短说明回答它控制什么、失守后打开什么方向、哪些位置仍有争议。

### P-005：距离和尺度

查看相邻节点。

预期：

- 显示约略距离或提供直接量测。
- 明确距离基于现代代表点和指定算法，不等同于历史行军里程。
- 不用六位坐标精度暗示历史精确性。

### P-006：事件与地形共同解释

从潼关固守浏览至出关、灵宝方向交战、潼关失守和长安后果。

预期：

- 路线阶段和短解释随事件更新。
- 地形基底、河流、关隘和基本定位保持稳定，用户不会因切换事件失去空间参照。
- 5—10 次核心交互可以讲清战争进程及地形原因。

### P-007：地图优先信息层级

在 1024×768 和 1440×900 观察首屏。

预期：

- 地图占主要视野，潼关、路线、主要地貌和短解释同时可见。
- 时间轴和引用不遮挡地图；完整引用按需展开。
- 图例、图层控制、比例尺、署名和解释面板不重叠。

## 4. 地形与地图功能验收

### M-001：地形默认可见

- 正常模式首次加载即显示 hillshade/分层设色或等效地形表达。
- 关闭地形后能明显看出信息减少，从而证明地形不是装饰性叠层。
- 倾斜/三维为可选增强；俯视模式仍必须具备足够地形可读性。

### M-002：水系与流向

- 黄河、渭河标签可读。
- 流向表达不会被路线误认，也不会暗示唐代精确河道。
- 水系开关不破坏路线、地点和事件状态。

### M-003：山地、平原和通道

- 秦岭及当前相关山地区域可辨认。
- 至少一个平原/低地和东入关中通道具有可见表达。
- 通道的几何、宽度和说明可追溯到处理记录及审核决定。

### M-004：关隘语义

- 关隘、城市、战场使用不同形状或图标，不只依赖颜色。
- 潼关在不同缩放级别保持可发现，但不会无限放大成虚假精确范围。

### M-005：路线语义

- 行动方向、主体和当前阶段可稳定解码。
- 路线与地形通道视觉一致，但明确不等于历史道路中心线。
- 后退事件时未来路线立即隐藏；反复切换不重复图层。

## 5. 数据、内容与许可验收

- 每个 DEM、hillshade、行政边界、河流、地貌、通道、关隘和新增路线资产均有稳定 Source。
- Source 记录版本、机构、访问日期、覆盖范围、坐标系、许可链接、署名、限制和处理过程。
- 每条战争地理解释绑定 Citation 或明确的数据处理/项目推断记录。
- 现代地理事实、历史记载、现代研究、项目推断和争议在运行时语义与页面展示中可区分。
- PENDING_SOURCE、PENDING_REVIEW、CHANGES_REQUIRED、REJECTED 或缺审核人/日期的新增发布项不能进入正式集合。
- 不因产品负责人允许“约略解释”而编造页码、许可证、坐标、路线、历史里程或审核决定。
- 自动失败用例至少覆盖许可缺失、署名缺失、通道未批准、距离方法缺失、路线确定性错误和秘密进入构建。

## 6. 工程验收

- 固定并记录实际 Node/npm 版本，`npm ci` 与完整 `check` 通过。
- 地形资源构建或校验命令可重复执行，不依赖未记录的 GUI 操作。
- 根路径与 `/history-map/` 裸静态构建取得所有入口、数据、worker、地形和样式资源。
- 正常地形模式、地形失败降级和恢复路径均测试；只有正常地形模式可用于产品签字。
- 1024×768、1440×900 真实浏览器复核，正常 console 0 warning/error，单一 MapLibre/Canvas。
- 记录地形资产体积、请求数量、首次可交互时间和缓存行为；实际结果明显不可接受时必须先优化或缩小 bbox/缩放范围，不能隐瞒。
- 构建与跟踪文件不包含 Token、私钥、账号凭据、仅内部许可数据或未授权派生产物。
- 当前正式历史数据的既有不确定性和引用门禁继续通过。

## 7. 明确不作为本期失败条件

- 没有覆盖全国或安史之乱全部战线。
- 没有精确复原唐代河道、道路、城界、战场、兵力、速度或阵型。
- 没有路线高程剖面、替代路线模拟或连续军队动画等 P1 功能。
- 没有 Go、PostGIS、Martin、RAG、账号、多专题、完整手机布局或公开云部署。
- 没有把倾斜三维设为默认；只要默认俯视地形已经足以解释战争。
