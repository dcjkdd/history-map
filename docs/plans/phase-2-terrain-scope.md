# 安史之乱地形优先地图：二期范围

- 状态：当前可执行产品范围
- 日期：2026-08-02
- 决策依据：`docs/decisions/0002-地形优先二期产品纠偏.md`
- 基础代码：MVP-01—MVP-11 二维技术原型
- 核心切片：洛阳—陕州—灵宝—潼关—长安

## 1. 产品结论

二期的目标不是给现有时间轴增加一个好看的三维开关，而是交付项目第一版真正有用的产品形态：

> 用户先通过地形看懂军队为什么这样走，再用时间轴、详情和引用理解发生了什么以及哪些结论仍不确定。

二期必须证明：不需要精确复原唐代道路、兵力或战场边界，也能通过现代地形基底、经审核的历史节点和明确标注的解释性推断，形成有用且诚实的军事地理解释。

## 2. 必须回答的五个问题

用户进入默认页面后，应能在不展开长篇引用的情况下回答：

1. 洛阳、陕州、灵宝、潼关、长安今天大致位于哪里，横跨哪些省级区域？
2. 黄河、渭河、秦岭、平原和山地之间是什么空间关系？
3. 潼关为什么不是普通城市点，而是进入关中的关键关隘？
4. 洛阳向长安方向的军队为什么沿这条东西通道推进，北侧和南侧分别受到什么约束？
5. 关键节点之间大约相距多远；哪些距离、路线和地点只是现代代表点或解释性示意？

任一问题只能靠阅读侧栏长文回答，而不能从地图本身获得主要线索，均视为产品未完成。

## 3. 默认页面信息层级

```text
┌──────────────────────── 地图主视图（约 70%—80%） ────────────────────────┬──────── 解释面板 ────────┐
│ 地形起伏 / 分层设色 / 山体阴影                                             │ 当前关隘或路线为什么重要 │
│ 黄河、渭河及流向                                                           │ 2—4 条短解释             │
│ 省级定位、城市、关隘、平原、山地、通道                                     │ 不确定性和来源入口        │
│ 带方向和约略距离的解释性路线                                               │ 引用默认折叠              │
├────────────────────────── 紧凑事件轴 ────────────────────────────────────┴─────────────────────────┤
│ 上一事件 / 当前事件 / 下一事件；只改变路线阶段与短解释，不遮挡地图                                  │
└──────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

地图是第一视觉层；时间轴是路线阶段控制；引用是按需展开的信任层。不能再次让详情和引用占据主要视野，而地图只剩点线背景。

## 4. P0 地图层

| 层 | 最小交付 | 产品语义 |
|---|---|---|
| 地形基底 | 区域 DEM 派生的 hillshade 与分层设色，默认开启；支持俯视，具备可选倾斜/三维视角 | 一眼区分平原、山地、河谷与高低起伏 |
| 基本定位 | 省级边界和名称、指北、比例尺；至少覆盖河南、陕西及与当前视野直接相关的相邻区域 | 用户知道“现在在中国哪里” |
| 水系 | 黄河、渭河清晰标注，主要线段带流向语义 | 看见运输、阻隔和交汇关系 |
| 地貌 | 秦岭及当前叙事直接相关的山地、平原/盆地和狭窄通道；名称随缩放可读 | 看见哪些区域可通行、哪些区域构成约束 |
| 关隘 | 潼关使用独立关隘符号和地形解释标注，不能与普通城市只靠小色差区分 | 看见关隘控制的是哪条通道 |
| 城市节点 | 长安、洛阳、陕州、灵宝使用可读标签，古今对应和争议按需查看 | 建立故事节点和现代位置的联系 |
| 解释性路线 | 当前燕军西进、唐军出关方向使用带箭头的通道线或宽度带；避免端点间视觉直尺线 | 表达方向、阶段和地形通道，不冒充历史道路 |
| 距离 | 相邻代表点的直线距离或地图量测值，明确标注“约”“现代代表点间” | 提供尺度感，不冒充行军里程 |
| 军事地理注释 | 地图上可见的短标签，例如“北侧河流约束”“南侧山地约束”“向西进入关中” | 直接回答为什么这样走 |

## 5. P1 增强

- 俯视与倾斜地形视角切换，切换后标签和交互仍可用。
- 全国或区域定位小窗，帮助理解当前专题在中国的位置。
- 河流流向动画或重复箭头，但不能影响性能和可读性。
- 关隘剖面、路线高程剖面或坡度概览；只在数据来源和解释价值都明确时实现。
- 路线替代方向对比，用于说明绕行成本；不得凭想象生成历史路线。

P1 缺失不能掩盖 P0；P0 地形解释不成立时，不得用动画或复杂三维效果代替。

## 6. 内容与数据边界

### 6.1 可直接复用

- 5 个已有 Place、6 个 Event、3 个 Geography、3 个 RouteSegment。
- 已审核的 Source、Citation、SourcedClaim、争议说明和事件顺序。
- MapLibre 地图壳、图层注册与恢复、单一 store、时间轴、详情、引用和静态部署。

### 6.2 必须新增或重审

- DEM、hillshade、分层设色、行政边界、地貌区域和标签数据的来源、版本、许可和处理过程。
- 东入关中通道的几何形式及其“解释性通道”语义。
- 黄河、秦岭在当前战争叙事中的作用 Claim；现有范围外候选不能自动转为批准。
- 新增关隘或古道的名称、现代对应、位置和使用边界。
- 距离的计算方法和页面措辞；默认只允许“现代代表点间约略直线距离”。
- 任何路线宽度带、替代通道、坡度或剖面的数据来源和推断说明。

### 6.3 允许的不精确

- 现代 DEM 用于解释宏观地形，并明确不代表唐代地表细节。
- 河流和行政边界可以使用可许可的现代概览数据，并明确年代边界。
- 路线可以是低可信度解释性通道，不要求复原唐代道路中心线。
- 城址和战场可继续使用 DISPUTED 代表点或范围，但地图不能用视觉精度暗示其已确认。

“不精确但诚实”是允许的；无来源、无边界或把项目推断伪装成史实仍不允许。

## 7. 数据源与秘密门禁

PHASE2-01 必须先比较候选数据源，记录：

- 数据名称、发布机构、版本、访问日期、覆盖范围和分辨率。
- 原始坐标系、无效值、裁剪、重投影、编码、简化和切片过程。
- 许可证链接、再分发权、署名文字、Token/配额要求。
- 是否允许把派生产物提交进仓库或静态发布。
- 根路径和 `/history-map/` 部署方式，以及离线/降级表现。

没有完成上述记录前，不选择正式地形供应商，不提交 Token，不把开发者个人账号配额变成产品运行依赖。

## 8. 技术边界

- 继续使用 Vue 3、TypeScript、Vite、Pinia 和 MapLibre GL JS。
- 优先使用区域裁剪后的静态地形资产和 GeoJSON；先通过源审计与体积试验，再决定是否需要瓦片服务或 PMTiles。
- 不因二期自动引入 Go、PostgreSQL/PostGIS、Docker、Martin、RAG、登录或多专题。
- 允许增加少量经过审计的构建期地理处理脚本；运行时依赖必须另行说明必要性。
- 保持根路径与 `/history-map/` 裸静态部署能力、单一 MapLibre/Canvas 和 worker 闭包校验。

## 9. 明确不做

- 不复原全国古代战争地图，不扩展其他专题。
- 不承诺唐代精确河道、道路中心线、城界、战场边界、里程、速度、兵力或阵型。
- 不用完整三维中国模型、卫星影像或动画效果替代当前区域的可读解释。
- 不先建设后端、数据库、数据维护后台、RAG、用户系统或云部署。
- 不删除现有审核历史，不自动批准 PENDING/REJECTED 候选。

## 10. 产品完成定义

二期只有在以下条件同时成立时才能称为第一可用产品：

1. 默认地图无需侧栏长文即可看出地形、河流、关隘、节点、方向和尺度。
2. 用户能在 5—10 次交互内回答第 2 节五个问题。
3. 地形和军事地理层不是可有可无的装饰，而是路线解释的直接证据。
4. 新增数据与推断通过来源、许可、内容和不确定性门禁。
5. 产品负责人真实浏览器验收并明确签字；自动测试、内容行级批准和工程负责人签字均不能代替。
