# 安史之乱二维交互地图：MVP 验收标准

- 状态：发布门禁
- 对应范围：`docs/plans/mvp-scope.md`
- 对应任务：`docs/plans/mvp-tasks.md`

## 1. 验收原则

MVP 必须同时通过四类验收：

1. **产品验收**：用户能用地图和时间轴理解完整核心叙事。
2. **功能验收**：地图、路线、时间轴、详情和引用按预期工作。
3. **数据验收**：事实、坐标、时间、路线、引用和可信度经过自动与人工检查。
4. **范围验收**：没有用后端、三维、RAG、后台等非核心功能拖延交付。

“页面能打开”不等于验收通过；“自动测试通过”也不等于历史内容已经审核。

## 2. 验收前置条件

### 2.1 工程前置条件

在项目根目录执行：

```text
nvm use
node -v
npm -v
```

Node 必须与根目录 `.nvmrc` 一致。

在 `frontend/` 目录执行：

```text
npm ci
npm run check
```

`npm run check` 必须依次通过：

- TypeScript 类型检查
- MVP 数据校验
- 自动测试
- 生产构建

### 2.2 内容前置条件

1. `data/curated/anshi-mvp-source-notes.md` 存在。
2. 正式数据不是从占位模板直接发布。
3. `docs/reviews/anshi-mvp-content-review.md` 已生成并由内容负责人审核。
4. 所有拟发布数据行中的 `PENDING_SOURCE`、`PENDING_REVIEW`、`CHANGES_REQUIRED`、`TODO_REVIEW`、示例页码和占位坐标已清零；状态说明、空白模板和明确排除的记录不计入。
5. 进入正式数据的每个对象在资料笔记与审核表中的对应记录全部为 `APPROVED`，并填写真实审核人和审核日期；发布 JSON 本身不需要携带审核状态。
6. 每条对外展示结论已逐条绑定一个或多个 Citation；所有地点、路线和地理几何均可追溯到 Source。
7. 空间数据与外部底图的版本、许可证链接、署名要求和处理过程已核对。

### 2.3 环境前置条件

验收至少覆盖两种运行方式：

1. 配置有效 `VITE_MAP_STYLE_URL` 的正常底图模式。
2. 不配置外部底图的本地降级模式。

## 3. 发布阻断条件

出现以下任一情况，MVP 不得标记为完成：

- 应用无法启动或生产构建失败。
- 数据校验失败。
- 时间轴事件顺序错误或不稳定。
- 未来路线段在对应事件之前出现。
- 任一对外展示结论没有逐条 Citation 绑定，或关键事件、地点、路线、地理要素没有可解析来源。
- 页面把 LOW、DISPUTED、UNKNOWN 内容表现为确定事实。
- 地图底图失败后页面白屏或历史图层不可用。
- 存在编造页码、未经说明的精确日期、占位坐标，或空间数据缺少许可证/署名记录。
- 核心用户路径无法在一个页面内完成。
- 为完成 MVP 强制依赖 Go、PostgreSQL、Docker 或其他暂缓系统。

## 4. 功能验收用例

### A-001：应用启动与数据加载

**优先级：P0**

步骤：

1. 在 `frontend/` 执行 `npm run dev`。
2. 打开首页。

预期：

- 页面显示项目标题、地图区域、时间轴和详情区域。
- 数据加载完成后默认选中 `topic.defaultEventId`。
- 没有白屏、无限 loading 或未处理异常。

### A-002：无外部底图时降级运行

**优先级：P0**

步骤：

1. 不设置 `VITE_MAP_STYLE_URL`。
2. 启动页面。

预期：

- 显示中性空白底图。
- 地理要素、地点、路线、时间轴和详情仍可操作。
- 页面可提示当前使用降级底图，但不阻断使用。

### A-003：配置外部底图

**优先级：P1**

步骤：

1. 配置有效 `VITE_MAP_STYLE_URL`。
2. 启动页面。

预期：

- 外部底图正常加载。
- 历史图层位于合适层级，不被底图完全遮挡。
- 底图样式变化不影响历史数据结构和时间轴逻辑。

### A-004：初始地图视野

**优先级：P0**

步骤：打开页面，不进行缩放或拖动。

预期：

- 初始视野来自 `topic.initialView`。
- 潼关核心叙事区域可见或可通过一次“定位当前事件”进入。
- 初始视野没有硬编码到多个组件。

### A-005：地图基本交互

**优先级：P0**

步骤：拖动、放大、缩小地图。

预期：

- 操作流畅，无明显卡死。
- 时间轴和详情状态不因地图移动而丢失。
- 地图不会意外创建多个实例。

### A-006：图层开关

**优先级：P0**

步骤：分别关闭和重新打开地理要素、地点、路线。

预期：

- 每个图层组可独立控制。
- 关闭路线不影响时间轴事件切换。
- 反复开关不会重复添加图层或产生控制台错误。

### A-007：地点类型和可信度样式

**优先级：P0**

步骤：观察 CITY、PASS 及低可信度地点。

预期：

- 城池和关隘可明显区分。
- LOW、DISPUTED、UNKNOWN 有额外线型、边框或透明度语义，不只依赖颜色。
- 图例能解释这些差异。

### A-008：点击地点查看详情

**优先级：P0**

步骤：点击潼关、长安等地点。

预期：

- 侧栏切换为地点详情。
- 显示历史名称、现代对应、类型、战略作用、坐标说明、可信度和引用。
- 关闭地点详情后回到原来的事件详情，当前时间轴节点不改变。

### A-009：时间轴默认事件

**优先级：P0**

步骤：首次打开或刷新页面。

预期：

- 默认事件来自数据集配置。
- 时间轴、地图高亮和事件详情三者一致。

### A-010：上一事件 / 下一事件

**优先级：P0**

步骤：从第一个事件连续点击“下一事件”直到最后，再反向返回。

预期：

- 事件严格按 `sequence` 前进和后退。
- 第一个事件的“上一事件”和最后一个事件的“下一事件”正确禁用。
- 不跳号、不重复、不出现未知事件。

### A-011：直接选择时间轴节点

**优先级：P0**

步骤：点击中间任意事件，再点击其他事件。

预期：

- 当前事件标题、日期、详情、地点高亮和路线状态同步更新。
- 重复选择同一事件结果一致。

### A-012：路线逐段出现

**优先级：P0**

步骤：从第一个事件逐步前进。

预期：

- 路线段只在 `appearAtEventId` 对应事件或之后出现。
- 当前事件首次出现的路线段与此前路线段可区分。
- 返回前一事件时，未来路线段立即隐藏。
- 不存在“先看到结果路线，再读到事件”的信息泄露。

### A-013：阵营和行动类型辨识

**优先级：P1**

步骤：同时观察唐、燕、朝廷转移等路线。

预期：

- 不同主体至少能通过线型、粗细、方向符号或标签区分。
- 不只依赖红绿等颜色区分。
- 图例与详情中的命名一致。

### A-014：事件详情

**优先级：P0**

步骤：选择任一关键事件。

预期：

- 显示时间文本、发生了什么、为什么重要、相关地点、参与者、可信度和引用。
- `dateLabel` 与时间精度一致，不强行展示不存在的精确日期。
- 空字段不会显示 `null`、空冒号或无意义占位。

### A-015：引用展示

**优先级：P0**

步骤：查看事件和地点引用。

预期：

- 可识别资料标题、作者/版本、章节或页码。
- 项目归纳与原文摘录视觉上分开。
- 观点类型和可信度可见。
- 同一结论可以展示多个来源，并能从稳定结论 ID 精确解析到对应 Citation。

### A-016：争议和不确定信息

**优先级：P0**

步骤：查看至少一个 LOW、DISPUTED 或 UNKNOWN 实体。

预期：

- 页面明确说明不确定在哪里、原因是什么。
- 不使用“精确坐标”“确定路线”等绝对措辞。
- 用户无需查代码即可理解该信息不是确定事实。

### A-017：定位当前事件

**优先级：P1**

步骤：将地图拖离核心区域，点击“定位当前事件”。

预期：

- 地图定位到当前事件相关地点或路线范围。
- 单纯切换时间轴不会强制每次飞行，避免打断用户自主浏览。

### A-018：加载失败

**优先级：P0**

步骤：临时使 `mvp-v1.json` 不可访问或返回非法 JSON。

预期：

- 页面显示可读错误和重试入口。
- 不出现白屏。
- 控制台有可定位的开发错误，但没有未捕获 Promise 异常。

### A-019：桌面布局

**优先级：P0**

步骤：分别在 1024×768 和常见宽屏尺寸打开页面。

预期：

- 地图、时间轴、详情和控制按钮可操作。
- 关键按钮不被遮挡。
- 侧栏内容可滚动，地图区域不会被无限压缩。

### A-020：键盘可操作性

**优先级：P1**

步骤：使用 Tab 聚焦时间轴和按钮，使用键盘切换事件。

预期：

- 焦点可见。
- 上一/下一按钮可通过键盘触发。
- 禁用状态不会被误触发。

## 5. 数据与内容验收

### D-001：数据规模

必须满足：

- 12—20 个地点
- 10—15 个事件
- 3—5 条逻辑路线
- 10—25 个路线分段
- 4—8 个地理要素
- 2—3 个核心资料
- 不少于 15 个引用

数量不是唯一目标；所有对象必须服务于核心叙事。

### D-002：ID 和引用完整性

预期：

- ID 唯一。
- 所有 `relatedPlaceIds`、`citationIds`、`sourceId`、`appearAtEventId`、`fromPlaceId` 和 `toPlaceId` 都能解析。
- 不使用数组下标作为跨对象引用。

### D-003：事件顺序

预期：

- `sequence` 从 1 开始连续。
- `dateLabel` 与资料笔记一致。
- 无法确定具体日期时不伪造精确日期。
- `normalizedDate` 为空不影响时间轴排序。

### D-004：坐标和几何

预期：

- 所有几何使用 WGS84 经纬度。
- 经度、纬度合法。
- 地点没有简单使用现代行政中心冒充古城址，除非说明只是近似定位。
- 低可信度地点具有 `coordinateNote`。
- 路线几何与来源笔记或推断说明一致，不自动套用现代高速公路。
- 每个发布几何都能解析到具体 Source；空间数据版本、许可证链接、署名文字和处理过程完整。

### D-005：引用覆盖

预期：

- 每条对外展示结论至少关联一个 Citation；不能只在实体级笼统挂一组来源。
- Event 的 `summary` / `whyItMatters`、Place 的 `summary` / `strategicRole`、Geography 与 RouteSegment 的解释性文本均可逐条追溯。
- 关键 RouteSegment 至少一个 Citation；纯连接段若共用路线来源，应明确继承规则或直接关联。
- Source 书目信息足够区分版本；没有页码时提供可复核的稳定定位。

### D-006：观点与事实分离

预期：

- 原始史书记载、现代研究、项目推断和争议使用不同 `viewpointType`。
- 项目推断不能冒充史料原文。
- 冲突观点可并列，不强行合并成单一结论。

### D-007：核心叙事完整性

内容负责人应能依据页面回答：

1. 潼关与长安、洛阳、陕州、灵宝的空间关系是什么？
2. 黄河、渭河、秦岭或相关通道如何影响防御？
3. 唐军为何选择固守，出关后发生了什么变化？
4. 潼关失守后长安局势如何发展？
5. 哪些结论较确定，哪些路线、时间或解释仍有争议？

任一问题无法从当前页面和引用中得到连贯答案，均视为内容未完成。

### D-008：版权与摘录边界

预期：

- 页面以项目归纳为主。
- 原文摘录短小、必要并带明确出处。
- 不在静态数据中放入整章、连续大段文字或完整书籍内容。

## 6. 工程与质量验收

### Q-001：构建与测试

必须通过：

```text
npm run typecheck
npm run validate:data
npm run test
npm run build
npm run check
```

### Q-002：运行时依赖

预期：

- 构建产物为纯静态文件。
- 不需要 Go、PostgreSQL、PostGIS、Redis、Docker 或 MinIO。
- 业务数据只从版本化静态数据 API 加载。

### Q-003：控制台质量

预期：

- 正常操作过程无未处理异常。
- 不出现重复 source/layer、地图容器重复初始化、内存泄漏警告。
- 数据错误信息包含可定位的字段路径或实体 ID。

### Q-004：交互响应

在 MVP 目标数据量下：

- 时间轴切换、图层开关和详情切换应立即产生可见反馈。
- 不出现明显阻塞主线程的长任务。
- 外部地图瓦片网络延迟不计入历史数据交互性能，但必须有加载或降级状态。

### Q-005：数据体积

预期：

- `mvp-v1.json` 原始体积不超过 2 MB。
- 不在 JSON 中嵌入 base64 图片、PDF 或大段书籍原文。

### Q-006：最小可维护性

预期：

- 数据加载、地图层定义、时间轴逻辑和详情展示职责分离。
- 业务组件不直接依赖静态文件 URL。
- 不存在为了未来多专题而建立的复杂插件体系。
- 新增一个事件或地点不需要修改多个硬编码列表。

## 7. 明确不作为本期失败条件的项目

以下功能缺失不能阻止 MVP 验收，因为它们明确不在第一期范围内：

- Go 后端、REST 管理 API
- PostgreSQL / PostGIS
- 数据维护后台
- 3D 地形、DEM、hillshade
- Martin、MVT、PMTiles
- ECharts 图表
- 自动播放和连续行军动画
- 人物详情页、战役详情页
- 搜索、多专题切换
- RAG、AI 问答、PDF 自动解析
- 登录、笔记、协作和审核工作流
- 完整移动端体验
- SEO 和公开发布运维

若这些功能已经进入代码并增加了构建或运行依赖，应视为范围偏离，而不是额外加分。

## 8. 缺陷分级和发布门禁

| 级别 | 示例 | 发布要求 |
|---|---|---|
| Blocker | 无法启动、数据校验失败、路线时间泄露、关键引用缺失、白屏 | 必须为 0 |
| Major | 图层开关失效、地点无法点击、时间轴与详情不同步、降级底图不可用 | 必须为 0 |
| Minor | 个别间距、文字换行、非关键样式不一致 | 可记录后发布，但需有清单 |

## 9. 最终签字清单

### 产品负责人

- [ ] 核心故事在 5—10 次交互内可以讲清。
- [ ] 页面没有被非核心功能干扰。
- [ ] 地图、时间轴和详情的信息层级清楚。

### 内容负责人

- [ ] 地点、事件、地理要素、实际路线分段、逐条结论、引用和资料版本全部审核。
- [ ] 坐标、时间和争议信息没有被过度确定化；空间数据许可证、署名和处理过程已核对。
- [ ] 不存在编造页码、占位数据和未说明推断。

### 开发负责人

- [ ] `npm run check` 通过。
- [ ] 正常底图和降级底图均通过验收。
- [ ] 无 Blocker 和 Major 缺陷。
- [ ] 构建产物不依赖后端或数据库。

三方全部通过后，第一期 MVP 才可标记为完成。
