# ADR-0002：地形优先的二期产品纠偏

- 状态：已确认
- 日期：2026-08-02
- 决策人：产品负责人在当前任务中明确确认
- 取代范围：第一期 MVP 的产品完成判断；不抹除 MVP-01—MVP-11 的工程和审核历史

## 背景

项目最初目标是“用真实地形解释中国古代战争”，重点回答山脉、河流、平原、关隘、距离和通道如何限制军队移动。第一期为了缩小工程风险，将 DEM、hillshade 和三维地形推迟，只实现 5 个地点、3 个现代背景要素、3 个解释性路线段、6 个事件、详情、引用和不确定性。

该版本证明了静态数据、MapLibre 图层、时间轴、引用、构建和发布门禁可以工作，但真实浏览器验收后，产品负责人明确指出：页面不能直观看出山川形势、关隘作用、所在区域、基本距离和路线为何如此选择，因此没有验证项目的核心价值。

原验证逻辑要求“先用缺少地形解释力的二维版证明地形解释战争有价值”，属于倒置验证。工程通过、内容行级批准和浏览器无错误均不能弥补这一产品缺口。

## 决策

1. MVP-01—MVP-11 的现有成果保留为“二维技术原型”，不再称为用户期望的第一可用产品。
2. MVP-11 的产品最终签字暂停；在地形优先二期通过新的产品验收前，不把整期产品标为完成或发布。
3. 二期不是锦上添花的三维效果增强，而是下一版产品的核心交付，权威范围、任务和验收分别由以下文档定义：
   - `docs/plans/phase-2-terrain-scope.md`
   - `docs/plans/phase-2-terrain-tasks.md`
   - `docs/plans/phase-2-terrain-acceptance.md`
4. 二期默认视图必须直接呈现可读地形。实现可采用 DEM、hillshade、分层设色和可选倾斜/三维视角；不能再次以中性空白底图作为产品完成证据。
5. 黄河、渭河、秦岭、平原/山地、东入关中通道、潼关关隘、节点距离和解释性路线必须形成同一张可读地图；时间轴、详情和引用改为辅助地图解释。
6. 不以“历史路线无法精确复原”为由省略空间解释。允许展示有明确边界的现代地形基底、代表点直线距离和解释性通道，但必须区分现代地理、历史资料、项目推断和争议，继续保留来源、许可和可信度。
7. 二期先复用现有 Vue、MapLibre、Pinia、静态数据和测试架构；除非地形数据源验证证明静态方案不可行，不提前引入 Go、PostGIS、Martin、RAG、账号或多专题平台。
8. 地形、行政定位和空间数据源必须先完成版本、覆盖范围、许可证、署名、处理过程、离线可复现性和秘密边界审计，再进入发布构建。

## 当前文档权威顺序

发生冲突时按以下顺序处理：

1. 用户当前明确要求。
2. 本 ADR。
3. 二期范围、验收、任务文档。
4. 第一阶段 MVP 文档（仅作为技术原型历史和可复用工程约束）。
5. ADR-0001 与长期架构、产品、开发文档。

内容发布仍以资料笔记、内容审核表和真实人工批准为准；本 ADR 不批准任何新的历史事实、坐标、路线、许可证或审核状态。

## 结果

- 保留现有工程资产，不推倒已验证的数据加载、图层、时间轴、详情、引用和部署能力。
- 产品优先级从“事件顺序和引用完整”调整为“先看懂地形约束，再通过事件和引用深入”。
- 二期产品验收将以用户能否直接回答“在哪里、地形怎样、为什么经过这里、关隘为何重要、距离大致多少”为核心。
- 若地图必须依赖长篇侧栏文字才能解释路线原因，即使测试和内容审计全部通过，产品仍判定失败。
