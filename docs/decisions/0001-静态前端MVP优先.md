# ADR-0001：静态前端 MVP 优先于长期后端架构

- 状态：已接受
- 日期：2026-07-29
- 适用范围：安史之乱第一期 MVP

## 背景

长期规划采用 Vue、Go、PostgreSQL/PostGIS，并继续演进到三维地形、知识库和多专题平台。这个方向仍然有效，但它同时包含了产品验证、数据平台和长期扩展能力。

第一期当前只需验证一个更小的问题：用户能否通过二维地图、离散事件、逐段路线、史料引用和可信度说明，理解“潼关防线、灵宝出战与长安失守”这一条叙事链。

## 决策

1. 第一可发布 MVP 使用 Vue 3、TypeScript、Vite、MapLibre GL JS 和版本化静态 JSON。
2. MVP 运行时不依赖 Go、PostgreSQL/PostGIS、Docker、Martin、RAG 或三维地形。
3. 数据访问统一经过 `MvpRepository`，UI 不直接读取静态文件；未来后端化时通过适配层替换数据来源。
4. 项目唯一根目录是 `/Users/banq/Documents/history-map`。README、`docs/`、`frontend/`、`data/` 等目录都位于该根目录下。
5. 前端开发环境固定为 `.nvmrc` 中的 Node.js 24.18.0；不修改其他项目使用的 NVM 全局默认版本。
6. 第一阶段历史内容必须先进入人工资料笔记和审核清单。没有明确版本、出处、坐标依据和可信度的内容不能进入正式发布数据。

## 文档权威顺序

发生实施冲突时，按以下顺序判断：

1. 用户在当前任务中的明确要求。
2. `docs/plans/mvp-scope.md` 的 P0 范围与明确暂缓项。
3. `docs/plans/mvp-acceptance.md` 的发布门禁。
4. `docs/plans/mvp-tasks.md` 的任务定义。
5. 本 ADR。
6. `docs/architecture/`、`docs/development/` 中的长期目标架构和阶段规划。

长期文档没有失效；它们描述的是 MVP 验证通过后的演进方向，不再作为当前 MVP 必须同时实现的范围。

## 后端重新进入计划的条件

满足以下任一条件时，单独评审 Go 和 PostGIS 的引入：

- 需要在线编辑、审核或多人协作。
- 开始支持多个专题或对外查询 API。
- 静态 JSON 维护成为明确瓶颈。
- 需要视野范围查询、空间相交或其他服务端空间计算。
- 数据规模造成经过实测的加载或维护问题。

## 影响

- 优点：第一期可以更快验证核心叙事与引用体验，部署和回退简单。
- 代价：静态数据仍需严格校验，内容更新需要重新构建发布。
- 约束：不能把静态数据便利性作为编造坐标、页码或精确日期的理由。
