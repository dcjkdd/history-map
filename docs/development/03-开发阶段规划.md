# 开发阶段规划

> 文档定位：长期演进规划。2026-08-02 起，当前执行阶段是 [第二期地形优先产品纠偏](../plans/phase-2-terrain-scope.md)，决策依据见 [ADR-0002](../decisions/0002-地形优先二期产品纠偏.md)。MVP-01—MVP-11 完成的是静态前端技术原型，不是产品价值验收；后端、数据库、RAG 和多专题仍暂缓。

## 第零期：项目骨架与数据设计

目标：项目能启动，核心数据模型稳定。

- 建立 Git 仓库和目录
- 创建 Vue 和 Go 项目
- Docker Compose 启动 PostGIS
- 建立数据库迁移
- 定义地点、人物、事件、战役、路线、资料和引用模型
- 建立安史之乱专题

交付标准：

- 前后端可以启动
- 数据库可以初始化
- 能保存并查询一个地点

## 第一期：二维技术原型（工程完成，产品验证未通过）

目标：验证静态数据契约、内容审核、MapLibre 图层、时间轴、详情引用、构建部署与浏览器交互链。

- MapLibre 基础地图
- 地点、关隘、战场标记
- 河流和路线图层
- 图层开关
- 地点详情面板
- 安史之乱时间轴
- 行军路线逐段展示
- 资料来源和页码
- 简单数据维护页面

交付标准：

- 可以通过时间轴理解主要事件顺序
- 可以点击地点查看历史作用和资料出处
- 可以展示 5—10 条核心路线

实际结论：工程与内容审计链成立，但中性二维底图、少量点位和直线无法让用户理解山川形势、关隘作用或行军原因，因此不得称为第一可用产品。

## 第二期：地形优先的第一可用产品（当前执行）

当前实施状态：PHASE2-01 已在提交 `a88fbd2` 完成来源审计与视觉试验；PHASE2-02 已在提交 `ab3ac2d` 完成正式静态地形、现代省级定位、工程门禁、浏览器复验和产品视觉确认并推送。PHASE2-03 尚未启动，其内容候选、人工审核、实现和产品验收必须分别记录。

- 建立可审计的 DEM/地形瓦片或等效高程数据来源、版本、许可、署名和处理记录
- 默认可见的山体阴影与地形分层配色；三维倾斜视角是可选增强，不替代清晰二维判读
- 省级方位参照、现代地名辅助定位和专题范围概览
- 黄河、渭河、秦岭、关中平原、崤函—潼关通道等核心军事地理
- 关隘专用表达以及“山—河—关—道”的空间关系
- 路线方向、关键节点、大致距离和基于地形的解释；不伪造精确古道几何
- 地图优先布局，时间轴和引用详情压缩为辅助叙事
- 复用现有不确定性、引用和人工审核门禁

交付标准：

- 用户不依赖长篇说明即可指出洛阳、陕州、灵宝、潼关、长安的大致方位和路线方向
- 用户能从地图直接看出潼关为何构成长安东面的关键通道控制点
- 用户能解释军队为什么沿黄河—崤函—潼关一线行动，以及山地、河流、平原和距离造成的约束
- 正式地形、边界、通道、距离和军事解释全部有来源、许可、审核与不确定性边界

详细拆分以 [第二期任务](../plans/phase-2-terrain-tasks.md) 和 [第二期验收标准](../plans/phase-2-terrain-acceptance.md) 为准。

## 第三期：知识库与自动导入

- PDF / EPUB / Markdown 上传
- 文档解析和切片
- pgvector
- 地点、人物、年份实体提取
- 人工确认流程
- 带引用 AI 问答
- 多资料观点对比

交付标准：

- 地图点击地点可以检索相关书籍段落
- AI 回答包含资料、章节和页码
