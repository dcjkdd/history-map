# 总体架构

## 1. 架构目标

系统需要同时承载五类能力：

1. 地图展示：地形、河流、城市、关隘、古道、战场。
2. 历史时间：按年份或事件推进，改变地点、路线和势力状态。
3. 战争叙事：人物、战役、行军路线、粮道和战略解释。
4. 史料引用：所有重要判断可以追溯到书籍、章节、页码或原始资料。
5. 持续扩展：先做安史之乱，以后增加三国、楚汉、宋金、明末等专题。

## 2. 推荐架构

```text
浏览器
└── Vue 3 + MapLibre GL JS
    ├── 地图图层、3D 地形、标注
    ├── 时间轴、专题筛选
    ├── 地点、人物、战役详情
    └── 史料引用与知识问答
             │
             ▼
Go API（Gin）
├── 地点、人物、事件、战役 API
├── 路线和时间轴 API
├── GeoJSON API
├── 后台维护 API
├── 资料与引用 API
└── 知识库编排 API（后期）
             │
      ┌──────┴────────┐
      ▼               ▼
PostgreSQL + PostGIS   文件存储
├── 业务数据           ├── PDF / EPUB / Markdown
├── 空间数据           ├── 图片与地图资料
├── 历史有效期         └── DEM / PMTiles（后期）
└── pgvector（后期）
      │
      ▼
Martin（后期）
└── PostGIS → MVT 矢量瓦片
```

## 3. 第一阶段最小架构

```text
Vue 3 + MapLibre
        ↓
Go + Gin
        ↓
PostgreSQL + PostGIS
```

第一阶段不需要：

- Kubernetes
- Spring Cloud
- Kafka
- Elasticsearch
- Redis
- MinIO
- 独立向量数据库
- 微服务

## 4. 职责边界

### Vue / MapLibre

负责地图交互和展示，不承担历史规则判断。

### Go API

负责业务查询、权限、数据管理、时间轴组装和对外接口。

### PostGIS

负责空间存储和空间计算，例如：

- 视野范围内地点查询
- 地点附近战役
- 路线经过区域
- 点、线、面空间关系
- GeoJSON 输出

### Martin

数据量增加后负责矢量瓦片，不替代 Go 业务 API。

### QGIS / GDAL

用于地图数据加工和人工校正，不属于线上业务服务。
